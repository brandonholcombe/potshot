# UI — Pre-join server status panel (+ status endpoint)

## Author: fable-primary
## Status: Complete (2026-08-04) — live status JSON verified from cluster; pause EventSystem fix shipped; gate 61/61; deployed e3f4bd7

Brandon (2026-08-04): "selecting play online does not provide a room
browser or anything. Just straight into the action." One server = one
room by design (M0), so the right UX is a pre-join panel showing the
room before you commit. This pulls the M4 status endpoint forward in
minimal form.

## Design

1. **PotshotStatus (Potshot.Net, on the NetworkHub)**: when the SERVER
   starts, run an HttpListener on port 8080 (background thread; requests
   answered from a volatile snapshot struct the main thread refreshes
   each second — no Unity API off-thread). GET /status →
   `{"version":"0.1.0+dev","map":"DevArena","players":N,"bots":M,
   "uptimeSec":T}` (players = active human connections, bots = bot
   count; via PlayerSpawner/ServerManager). Stops with the server.
   JSON via hand-rolled string (no dependency).
2. **Menu flow**: Play Online → StatusPanel (generated by UIFactory):
   "Checking potshot.kodloki.io…" → UnityWebRequest GET
   `http://host:8080/status`, 4 s timeout.
   - Online: "SERVER ONLINE — 2 players · 3 bots · DevArena · v0.1.0"
     with JOIN (existing launch path) and BACK.
   - Unreachable: "Server unreachable" with JOIN ANYWAY and BACK.
   - Version mismatch (local GameVersion != server): warn in red — the
     authenticator would kick anyway; the panel explains it first.
3. **K8s**: deployment adds hostPort 8080/TCP (interim direct-port; the
   ingress + status.potshot.kodloki.io TLS route remains M4).
4. **Tests**: PlayMode — host in-process (per-test HTTP port), then
   UnityWebRequest localhost:<port>/status returns 200 + parseable
   fields matching live counts. EditMode — snapshot→JSON formatting.
   Post-deploy E2E: curl http://potshot.kodloki.io:8080/status from the
   Mac.
5. Pause-menu EventSystem fix ships in the same change (done ad-hoc,
   Brandon-reported: game scenes had no EventSystem → dead buttons).

## Risks (reviewer: verify)

- HttpListener in Unity Mono player builds on Linux: supported? Prefix
  form ("http://*:8080/" vs "+:8080") and non-root binding.
- macOS App Transport Security vs plain-http UnityWebRequest from the
  Mac client (Unity mac player Info.plist NSAllowsArbitraryLoads
  default?) — if blocked, fallback is a raw TcpClient HTTP GET or
  https-later-in-M4.
- Thread lifetime: listener must die on server stop AND app quit
  (no zombie threads holding the port across domain reloads in tests).
